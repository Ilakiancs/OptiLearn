# OptiLearn Fine-Tuning Pipeline

> **TL;DR** — We built a complete QLoRA fine-tuning pipeline for Gemma 4 using Unsloth, ran it, measured the results honestly, and made a data-driven deployment decision. The base model with domain-specific prompting won. The pipeline and data are here for the next iteration.

---

## The Experiment

OptiLearn needed a tutor that:
- Never gives direct answers — guides with questions and analogies (Socratic method)
- Never uses words like *wrong*, *incorrect*, *failed*, *mistake* (trauma-aware tone)
- Responds in the student's language, not the tutor's (multilingual compliance)
- Keeps responses to 3–5 sentences with a checking question at the end

We hypothesised that fine-tuning Gemma 4 on domain-specific tutoring data would outperform prompting alone. We built the pipeline, ran it on a Kaggle A100, and measured the outcome.

**What we found:** After 2 epochs of QLoRA fine-tuning on 11,500+ synthetic examples, the base Gemma 4 model with a carefully engineered system prompt outperformed the fine-tuned variant on all three pedagogical quality dimensions.

This is a known phenomenon: strong instruction-tuned base models (like Gemma 4) can match or beat domain fine-tunes when the training data has low diversity. Template-generated synthetic dialogues teach the model surface patterns, not genuine tutoring judgment. The base model's broader training generalises better.

See [`FINDINGS.md`](./FINDINGS.md) for the full benchmark breakdown.

## The Data

Two datasets exist in `data/`:

**Real tutoring conversations** (`optilearn_sft_train.jsonl`, `optilearn_sft_eval.jsonl`)
- 2,109 genuine student–tutor exchanges collected from real tutoring sessions
- Average 9 turns per conversation, up to 44 turns
- Students write like real students: casual, uncertain, frustrated, code-switching
- Covers math (fractions, derivatives, algebra), science, and literacy
- This is the data that matters for the next fine-tuning run

**Synthetic dataset** (generated by `01_prepare_dataset.py`, not committed — too large)
- 11,500+ examples generated from curated templates
- Three sources: Khan Academy-style Socratic dialogues, UNHCR trauma-informed scenarios, multilingual QA
- Languages: Arabic, French, Swahili, Somali, Amharic, Tigrinya, Dinka, Hausa
- Run `python finetuning/01_prepare_dataset.py` from repo root to regenerate

## Running on Kaggle

The `kaggle_notebook.ipynb` runs the full pipeline end-to-end.

**Prerequisites:**
- Kaggle account with GPU enabled (A100 recommended)
- HuggingFace account with write-access token
- Two Kaggle Secrets (Add-ons → Secrets): `HF_TOKEN`, `HF_USERNAME`

**Steps:**
1. Upload `finetuning/kaggle_notebook.ipynb` to a new Kaggle notebook
2. Enable GPU accelerator (A100 preferred, T4 x2 works)
3. Add `HF_TOKEN` and `HF_USERNAME` to Kaggle Secrets
4. Attach the `finetuning/` directory as a dataset
5. Run all cells — expected runtime ~3.5 hours on A100

Cell sequence: install deps → verify GPU → generate dataset → fine-tune → benchmark → publish to HuggingFace

## Running locally after training

```bash
# 1. Download finetuning/outputs/polytutor-weights/ from Kaggle output panel
# 2. Clone llama.cpp
git clone https://github.com/ggerganov/llama.cpp

# 3. Convert and register (run from repo root)
python finetuning/04_export.py

# 4. Verify
ollama list  # → polytutor-gemma4 should appear
```

To switch the app to the fine-tuned model:
```bash
# in optilearn/.env
USE_LOCAL_OLLAMA=true
OLLAMA_MODEL=polytutor-gemma4
```

## What's next

The real-data conversations in `data/` are the right foundation for the next iteration. 2,109 genuine multi-turn exchanges have more signal than 11,500 synthetic templates. A future run using only the real data — or real data augmented with LLM-generated high-diversity conversations — is the most promising path to a fine-tune that outperforms prompting.

## Troubleshooting

| Problem | Fix |
|---|---|
| OOM on A100 | Reduce `per_device_train_batch_size` to `1` in `02_finetune.py` |
| GGUF conversion fails | Ensure `llama.cpp` is cloned and Python 3.10+ |
| Ollama model not found | `ollama create polytutor-gemma4 -f finetuning/Modelfile` |
| `langdetect` import error | `pip install langdetect` |
| HuggingFace push fails | Check `HF_TOKEN` has write permissions |
| Training loss stuck | Verify `combined_train.jsonl` has 11,500+ examples |
